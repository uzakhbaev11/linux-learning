# Модуль 11. SSH

> ⏱ ~2 занятия по часу

**SSH** (Secure Shell) — зашифрованный удалённый вход на сервер. Это главный инструмент DevOps:
каждый деплой, каждая починка прода начинается с `ssh`.

```bash
ssh deploy@85.143.22.7          # войти на сервер как пользователь deploy
ssh -p 2222 deploy@85.143.22.7  # если SSH слушает нестандартный порт
exit                            # выйти (или Ctrl+D)
```

> 💡 В Linux на этом сайте есть настоящий SSH-сервер и пользователь **`deploy`** (пароль `deploy`).
> Он играет роль удалённого сервера: `ssh deploy@localhost`. Всё остальное — как в жизни.

## Пароль или ключ?

Вход по паролю — плохая идея: пароль можно подобрать, а боты перебирают пароли на всех серверах интернета круглосуточно.

Вход по **ключу** надёжнее и удобнее. Ключ — это пара файлов:
| Файл                     | Что это                          | Кому показывать |
|--------------------------|----------------------------------|-----------------|
| `~/.ssh/id_ed25519`      | **приватный** ключ               | НИКОМУ 🔒        |
| `~/.ssh/id_ed25519.pub`  | **публичный** ключ (`.pub`)      | кому угодно     |

Публичный ключ кладут на сервер в `~/.ssh/authorized_keys`. Сервер проверяет, что у тебя есть
парный приватный ключ, и пускает без пароля.

## Создать ключ

```bash
ssh-keygen -t ed25519 -C "my-laptop"
```
- `-t ed25519` — современный тип ключа (короткий и надёжный)
- `-C` — комментарий, чтобы потом понять, чей это ключ
- на вопрос о файле жми `Enter` (по умолчанию `~/.ssh/id_ed25519`)
- passphrase — пароль на сам ключ; на учёбе можно оставить пустым

## Права — SSH очень строгий

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519      # приватный ключ: только владелец
chmod 644 ~/.ssh/id_ed25519.pub
chmod 600 ~/.ssh/authorized_keys # на сервере
```
Если права слишком открытые, SSH **откажется** использовать ключ (`UNPROTECTED PRIVATE KEY FILE!`).

## Положить ключ на сервер

```bash
ssh-copy-id deploy@85.143.22.7
```
Последний раз спросит пароль и допишет твой `.pub` в `~/.ssh/authorized_keys` на сервере.
Дальше `ssh deploy@85.143.22.7` пускает без пароля.

## known_hosts: «а это точно мой сервер?»

При первом подключении SSH спросит:
```
The authenticity of host 'localhost' can't be established.
ED25519 key fingerprint is SHA256:....
Are you sure you want to continue connecting (yes/no)?
```
Ответ `yes` запоминает ключ сервера в `~/.ssh/known_hosts`. Если однажды ключ сервера изменится,
SSH поднимет тревогу `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!`. Так защищаются от подмены сервера.
Если сервер переустановили и ты знаешь об этом: `ssh-keygen -R адрес_сервера`.

## `~/.ssh/config` — короткие имена

Чтобы не помнить IP, пользователя и порт:
```
Host prod
    HostName 85.143.22.7
    User deploy
    Port 22
    IdentityFile ~/.ssh/id_ed25519
```
Теперь просто `ssh prod`. Это имя понимают `scp`, `rsync`, `git` и VS Code Remote.

## Команды на сервере без входа

```bash
ssh prod 'uptime'                       # выполнить и вернуться
ssh prod 'df -h' > disk.txt             # вывод сервера сохраняется у тебя
ssh prod 'tail -n 50 /var/log/app.log'
```

## Копирование файлов: `scp`

```bash
scp file.txt prod:~/                    # к себе → на сервер
scp prod:~/backup.tar.gz .              # с сервера → к себе
scp -r ./dist prod:/var/www/app/        # папку целиком (-r)
```

## Защита SSH-сервера

Настройки сервера лежат в `/etc/ssh/sshd_config` (именно **sshd** — d значит daemon, сервер):
```
PasswordAuthentication no     # вход только по ключам
PermitRootLogin no            # root не может войти напрямую
```
После изменения сервер нужно перезапустить:
```bash
sudo systemctl restart ssh      # Ubuntu (systemd, модуль 12)
sudo rc-service sshd restart    # Linux на этом сайте (Alpine, OpenRC)
```

⚠️ **Золотое правило:** прежде чем отключать пароли, убедись, что вход по ключу работает,
а текущую SSH-сессию не закрывай. Иначе закроешь дверь, а ключ останется внутри.

## 💼 В реальной работе

- Первым делом на новом сервере: свой пользователь, ключ, `PasswordAuthentication no`, `PermitRootLogin no`.
- GitHub тоже работает по SSH-ключам: `git clone git@github.com:...`.
- CI/CD (GitHub Actions) деплоит на сервер по SSH: приватный ключ хранится в секретах репозитория.
- Приватный ключ никогда не коммить в git и не отправляй в чат.
