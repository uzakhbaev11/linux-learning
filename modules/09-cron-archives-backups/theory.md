# Модуль 9. Cron, архивы, бэкапы

> ⏱ ~2 занятия по часу

«Бэкапов нет» — самая дорогая фраза в IT. В этом модуле ты научишься упаковывать данные в архивы,
писать скрипт бэкапа с ротацией и запускать его **по расписанию**, без участия человека.

## Архивы: `tar`

`tar` склеивает много файлов и папок в один архив, а `gzip` его сжимает. Вместе получается `.tar.gz` (или `.tgz`).

```bash
tar -czf backup.tar.gz myapp/          # создать (c) сжатый (z) архив-файл (f)
tar -tzf backup.tar.gz                 # посмотреть содержимое (t — list)
tar -xzf backup.tar.gz                 # распаковать (x) в текущую папку
tar -xzf backup.tar.gz -C /tmp/restore # распаковать в другую папку
tar -czf app.tar.gz --exclude=node_modules myapp/   # без лишнего
tar -czf app.tar.gz -C ~/projects myapp             # сначала перейти в ~/projects, потом упаковать myapp
```

Как запомнить флаги: **c**reate, e**x**tract, lis**t**, g**z**ip, **f**ile (после `f` сразу идёт имя архива), **v**erbose (подробно).

💡 Используй `-C`, чтобы внутри архива были **относительные** пути (`myapp/src/...`), а не `/home/student/...`.
Такой архив можно распаковать где угодно.

## Сжатие одного файла: `gzip`

```bash
gzip app.log           # app.log → app.log.gz (оригинал удаляется!)
gzip -k app.log        # то же, но оригинал остаётся (keep)
gunzip app.log.gz      # распаковать обратно
zcat app.log.gz        # прочитать, не распаковывая
zcat app.log.gz | grep ERROR
```

Так хранят старые логи: в `/var/log` ты увидишь `syslog.2.gz`, `nginx/access.log.3.gz`.

## Даты в именах файлов

```bash
date +%F               # 2026-11-27
date +%F_%H-%M         # 2026-11-27_14-05
tar -czf "backup_$(date +%F_%H-%M).tar.gz" data/
```

Формат `ГГГГ-ММ-ДД` удобен: при сортировке по имени файлы встают по порядку дат.

## Ротация: хранить только последние N

Бэкапы копятся, и однажды диск закончится. Поэтому старые удаляют:

```bash
ls -t backups/*.tar.gz                 # новые сверху (t — по времени)
ls -t backups/*.tar.gz | tail -n +4    # всё, КРОМЕ первых трёх (начиная с 4-го)
ls -t backups/*.tar.gz | tail -n +4 | xargs -r rm --   # удалить их

find backups -name "*.tar.gz" -mtime +7 -delete        # или: удалить старше 7 дней
```

`xargs` превращает строки из пайпа в аргументы команды. `-r` значит «не запускать `rm`, если строк нет».

## Cron: запуск по расписанию

Служба **cron** каждую минуту проверяет расписание и запускает то, что пора.

```bash
crontab -e      # редактировать своё расписание
crontab -l      # показать
crontab -r      # удалить ВСЁ расписание (осторожно!)
```

Формат строки: 5 полей времени, потом команда.

```
┌─ минута (0–59)
│ ┌─ час (0–23)
│ │ ┌─ день месяца (1–31)
│ │ │ ┌─ месяц (1–12)
│ │ │ │ ┌─ день недели (0–7, 0 и 7 — воскресенье)
│ │ │ │ │
* * * * *  команда
```

| Расписание          | Значит                         |
|---------------------|--------------------------------|
| `* * * * *`         | каждую минуту                  |
| `*/5 * * * *`       | каждые 5 минут                 |
| `0 3 * * *`         | каждый день в 03:00            |
| `30 9 * * 1-5`      | в 09:30 по будням              |
| `0 0 1 * *`         | первого числа каждого месяца   |

Проверить своё выражение можно на сайте crontab.guru.

### Три ловушки cron
1. **Другое окружение.** У cron короткий `PATH` и нет твоего `~/.bashrc`. Пиши **полные пути**: `/home/student/backup.sh`.
2. **Вывод пропадает.** Перенаправляй его в лог, иначе ошибок не увидишь:
   `* * * * * /home/student/backup.sh >> /home/student/backup.log 2>&1`
3. **Нет прав на запуск.** Скрипт должен быть исполняемым (`chmod +x`) и начинаться с shebang.

## 🔧 В реальной работе

```bash
# бэкап базы каждую ночь в 03:00, хранить 7 дней
0 3 * * * /opt/scripts/db_backup.sh >> /var/log/db_backup.log 2>&1
```

```bash
pg_dump shop | gzip > "/backups/shop_$(date +%F).sql.gz"
find /backups -name "shop_*.sql.gz" -mtime +7 -delete
```

И главное правило: **бэкап, который ни разу не пробовали восстановить, не считается бэкапом**.
