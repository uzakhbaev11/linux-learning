# Модуль 3. Работа с текстом и редакторы

> ⏱ ~2 занятия по часу

В Linux почти всё хранится в **текстовых файлах**: конфиги, логи, скрипты, `.env`.
Умение быстро читать, искать и править текст — это 80% работы на сервере.

## Чтение файлов

```bash
cat file.txt            # вывести весь файл (удобно для коротких)
less file.txt           # постраничный просмотр (для длинных)
head file.txt           # первые 10 строк
head -n 20 file.txt     # первые 20 строк
tail file.txt           # последние 10 строк
tail -n 50 app.log      # последние 50 строк
tail -f app.log         # следить за файлом В РЕАЛЬНОМ ВРЕМЕНИ (выход: Ctrl+C)
wc -l file.txt          # сколько строк в файле
```

### Управление в `less` (как в `man`)
| Клавиша       | Действие                    |
|---------------|-----------------------------|
| `Пробел` / `b`| страница вниз / вверх       |
| `g` / `G`     | в начало / в конец файла    |
| `/слово`      | поиск вперёд, `n` — дальше, `N` — назад |
| `q`           | выход                       |

### `tail -f` — лучший друг DevOps
Приложение упало? Открываешь логи и смотришь, что происходит прямо сейчас:
```bash
tail -f /var/log/nginx/error.log
```

## Поиск по тексту: `grep`

`grep` выводит только строки, в которых есть нужный текст.

```bash
grep "ERROR" app.log            # строки, содержащие ERROR
grep -i "error" app.log         # без учёта регистра (ERROR, Error, error)
grep -n "ERROR" app.log         # с номерами строк
grep -c "ERROR" app.log         # только количество совпадений
grep -v "INFO" app.log          # ИНВЕРСИЯ: строки, где НЕТ INFO
grep -w "user" app.log          # только целое слово (не найдёт "username")
grep -r "DB_PASSWORD" .         # искать во всех файлах папки рекурсивно
grep -A 3 "ERROR" app.log       # + 3 строки после совпадения (After)
grep -B 3 "ERROR" app.log       # + 3 строки до (Before)
```

### Чуть-чуть регулярных выражений
```bash
grep "^2026" app.log            # строки, НАЧИНАЮЩИЕСЯ с 2026
grep "ms$" app.log              # строки, ЗАКАНЧИВАЮЩИЕСЯ на ms
grep -E "ERROR|WARN" app.log    # ERROR ИЛИ WARN (-E = расширенные регулярки)
```

Реальный пример: «где в проекте используется переменная `DATABASE_URL`?»
```bash
grep -rn "DATABASE_URL" ~/myapp
```

## Редактор nano — простой

```bash
nano config.ini
```

Внизу экрана есть подсказки. `^` означает `Ctrl`.

| Клавиши    | Действие                    |
|------------|-----------------------------|
| `Ctrl+O`, затем `Enter` | сохранить (Write Out) |
| `Ctrl+X`   | выйти                       |
| `Ctrl+W`   | поиск (Where is)            |
| `Ctrl+K`   | вырезать строку             |
| `Ctrl+U`   | вставить                    |

## Редактор vim — мощный (и пугающий)

Зачем его знать: **vi/vim есть почти на любом сервере**, а nano есть не всегда.
Знаменитая шутка: «Как выйти из vim?» Сейчас ты научишься.

### Главная идея: у vim есть режимы
- **Normal** (обычный): сюда попадаешь при запуске. Клавиши здесь — это **команды**, а не текст.
- **Insert** (вставка): здесь печатаешь текст как обычно.
- **Command** (команды через `:`): сохранение, выход и т.д.

```
           i                    Esc
Normal  ───────►  Insert   ───────►  Normal
   │
   └── : ──► Command (:w, :q ...) ──► Enter
```

### Минимум, который надо знать
| Команда   | Действие                                  |
|-----------|-------------------------------------------|
| `i`       | войти в режим вставки (insert)            |
| `Esc`     | вернуться в Normal                        |
| `:w`      | сохранить                                 |
| `:q`      | выйти                                     |
| `:wq`     | сохранить и выйти                         |
| `:q!`     | выйти БЕЗ сохранения (паника! 😱)         |
| `dd`      | удалить строку                            |
| `u`       | отменить                                  |
| `/текст`  | поиск                                     |
| `gg` / `G`| в начало / конец файла                    |

💡 Если в vim что-то пошло не так: **жми `Esc` несколько раз, затем `:q!` и `Enter`**.

Для тренировки vim есть встроенный учебник: `vimtutor` (~30 минут, очень рекомендую).
