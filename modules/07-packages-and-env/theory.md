# Модуль 7. Пакеты и окружение

> ⏱ ~2 занятия по часу

Чтобы запустить бэкенд на сервере, нужно две вещи: **поставить программы** (язык, базу, утилиты)
и **настроить окружение** (переменные, `PATH`, секреты в `.env`). Об этом модуль.

## Менеджер пакетов

Программы в Linux не скачивают с сайтов: их ставит **менеджер пакетов** из проверенного **репозитория**.
Он сам подтянет зависимости и потом сам всё обновит.

| Действие                       | Ubuntu / Debian (`apt`)      | Alpine (`apk`, наш Linux на сайте) |
|--------------------------------|------------------------------|------------------------------------|
| обновить список пакетов        | `sudo apt update`            | `sudo apk update`                  |
| установить                     | `sudo apt install jq`        | `sudo apk add jq`                  |
| удалить                        | `sudo apt remove jq`         | `sudo apk del jq`                  |
| найти пакет                    | `apt search json`            | `apk search json`                  |
| информация о пакете            | `apt show jq`                | `apk info -a jq`                   |
| список установленных           | `apt list --installed`       | `apk info`                         |
| какой пакет владеет файлом     | `dpkg -S /usr/bin/htop`      | `apk info --who-owns /usr/bin/htop`|
| обновить всё                   | `sudo apt upgrade`           | `sudo apk upgrade`                 |

💡 `update` обновляет **только список** доступных пакетов, а не сами программы.
Поэтому перед `install` на свежем сервере сначала делают `update`.

> В браузере у Linux нет интернета, поэтому внутри лежит маленький **локальный репозиторий**
> с парой пакетов (`jq`, `figlet`). Команды при этом настоящие, как на сервере.

## Где лежат команды: `PATH`

Когда ты пишешь `ls`, shell ищет файл `ls` в папках из переменной `PATH` (через `:`, по порядку):

```bash
echo $PATH              # /usr/local/bin:/usr/bin:/bin:...
command -v ls           # где лежит команда: /bin/ls
which htop              # то же самое (почти)
type cd                 # cd is a shell builtin — встроена в сам bash
type ll                 # покажет, если это alias
```

Нет папки в `PATH` — команду придётся запускать по полному пути: `./script.sh`, `~/bin/tool`.
Отсюда частая ошибка `command not found`: программа есть, но её папки нет в `PATH`.

## Переменные окружения

```bash
NAME=shop               # переменная shell (БЕЗ пробелов вокруг =)
echo $NAME              # shop
export NAME             # сделать её переменной ОКРУЖЕНИЯ — её увидят дочерние программы
export PORT=3000        # объявить и экспортировать сразу
env                     # все переменные окружения
printenv HOME           # одна переменная
unset NAME              # удалить переменную
PORT=4000 ./start.sh    # задать переменную только для ОДНОЙ команды
```

Главное правило: **скрипт видит только экспортированные переменные**. Без `export` переменная живёт
только в твоём текущем shell.

## `~/.bashrc`: настройки, которые не пропадают

Всё, что ты задал командой, исчезнет, когда закроешь терминал. Чтобы настройка была всегда,
её пишут в `~/.bashrc`: bash выполняет этот файл при каждом запуске.

```bash
# в конец ~/.bashrc
export PATH="$HOME/bin:$PATH"     # свои скрипты из ~/bin запускаются по имени
alias ll='ls -la'                 # сокращение
alias gs='git status'
```

После правки перечитай файл: `source ~/.bashrc` (или открой новый терминал).

## Секреты и `.env`

Пароли, токены и ключи API **никогда не пишут в код** и не коммитят в git. Их кладут в файл `.env`:

```bash
# .env
DB_PASSWORD=supersecret
APP_PORT=3000
```

```bash
chmod 600 .env                 # читать и писать может только владелец
set -a; source .env; set +a    # загрузить все переменные из .env и экспортировать их
```

`set -a` значит «экспортируй всё, что объявится дальше». Без него скрипт не увидит переменные.

## 🔧 В реальной работе

```bash
sudo apt update && sudo apt install -y nginx postgresql   # подготовка сервера
dpkg -S /usr/sbin/nginx           # «откуда этот файл?»
echo $PATH                        # «почему не находится node?» — проверь PATH
ls -l .env                        # -rw------- — секреты закрыты от других пользователей
```

Docker, systemd и CI/CD тоже передают настройки приложению через переменные окружения.
Поэтому `export`, `.env` и `PATH` встретятся тебе везде.
