# Модуль 10. Сеть

> ⏱ ~2 занятия по часу

Бэкенд — это программа, которая **слушает порт** и отвечает на запросы по сети.
Чтобы задеплоить его и понять, почему «сайт не открывается», нужно знать основы сети.

> 💡 У Linux на этом сайте **нет выхода в интернет**: он работает внутри браузера.
> Но сеть внутри одного компьютера (`localhost`) работает по-настоящему. Поэтому в заданиях
> твой Linux будет одновременно **и сервером, и клиентом**. Команды точно те же, что на настоящем сервере.

## IP-адрес и порт

- **IP-адрес** — адрес компьютера в сети: `192.168.1.10`, `85.143.22.7`.
- **Порт** — номер «двери» в компьютере. На одном сервере много программ, и каждая слушает свой порт.

Адрес программы = IP + порт: `85.143.22.7:443`.

| Порт  | Кто обычно слушает             |
|-------|--------------------------------|
| 22    | SSH (удалённый вход на сервер) |
| 80    | HTTP (сайты без шифрования)    |
| 443   | HTTPS (сайты с шифрованием)    |
| 5432  | PostgreSQL                     |
| 6379  | Redis                          |
| 3000, 8000, 8080 | твой бэкенд при разработке |

### Особые адреса
- `127.0.0.1` (имя `localhost`) — **этот же компьютер**. Пакеты не уходят в сеть.
- `0.0.0.0` — когда программа слушает этот адрес, она принимает подключения **со всех** адресов компьютера, то есть и снаружи.

Это важно для безопасности:
```
127.0.0.1:5432   ← база доступна только программам на этом сервере ✅
0.0.0.0:5432     ← база доступна всему интернету 😱
```

## Смотрим на сеть

```bash
ip a                  # сетевые интерфейсы и их IP-адреса (ip addr)
ip -br a              # то же коротко
ping -c 3 localhost   # отвечает ли компьютер? 3 пакета
```

`lo` — это интерфейс **loopback** с адресом `127.0.0.1`. Он есть всегда.
На сервере ты увидишь ещё `eth0` или `ens3` с внешним IP.

## Кто слушает порты: `ss`

```bash
ss -tlnp
```
- `-t` — TCP
- `-l` — только слушающие (listening) порты
- `-n` — номера портов цифрами, а не именами
- `-p` — какая программа слушает (для чужих процессов нужен `sudo`)

```
State   Local Address:Port   Process
LISTEN  0.0.0.0:22
LISTEN  *:8080               users:(("httpd",pid=1623,fd=3))
```

Классика: бэкенд не запускается с ошибкой `address already in use`. Значит, порт уже кто-то занял.
`ss -tlnp` покажет, кто именно.

## HTTP-запросы из терминала: `curl`

```bash
curl localhost:8080                 # GET-запрос, вывести тело ответа
curl -s localhost:8080              # тихо (без индикатора загрузки)
curl -o page.html localhost:8080    # сохранить ответ в файл
curl -i localhost:8080              # заголовки + тело
curl -I localhost:8080              # только заголовки (запрос HEAD)
curl -v localhost:8080              # подробно: весь диалог с сервером
curl -s -o /dev/null -w "%{http_code}\n" localhost:8080   # только код ответа
curl -X POST -d '{"a":1}' -H "Content-Type: application/json" localhost:8080/api
```

### Коды ответа HTTP
| Код  | Значение                               |
|------|----------------------------------------|
| 200  | OK, всё хорошо                         |
| 301/302 | редирект (перенаправление)          |
| 401 / 403 | нужна авторизация / доступ запрещён |
| 404  | Not Found, такой страницы нет          |
| 500  | ошибка внутри сервера (баг в бэкенде)  |
| 502  | Bad Gateway: nginx не достучался до бэкенда |

Запомни: **4xx — ошибся клиент, 5xx — ошибся сервер**.

## DNS и `/etc/hosts`

Люди пишут `google.com`, а компьютеру нужен IP. Перевод имени в IP делает **DNS**.

Но сначала Linux смотрит в файл **`/etc/hosts`**: там можно вручную задать имя → IP.
```
127.0.0.1   localhost
127.0.0.1   shop.local
```
```bash
getent hosts shop.local     # во что превращается имя
```

Менять `/etc/hosts` может только root:
```bash
sudo nano /etc/hosts
echo "127.0.0.1 shop.local" | sudo tee -a /etc/hosts     # дописать одной командой
```
⚠️ `sudo echo "..." >> /etc/hosts` **не сработает**: `>>` выполняет твой shell без прав root,
а `sudo` получает только `echo`. Поэтому используют `tee -a`.

## Firewall (брандмауэр)

Firewall решает, на какие порты пускать подключения снаружи. На Ubuntu-сервере это `ufw`:
```bash
sudo ufw allow 22        # SSH (сначала его, иначе закроешь себе вход!)
sudo ufw allow 80
sudo ufw allow 443
sudo ufw enable
sudo ufw status
```
В браузерном Linux ufw нет. Настроишь его по-настоящему в итоговом проекте на своём сервере.

## Учебный веб-сервер

В этом Linux есть простой веб-сервер `httpd` (из busybox). Он раздаёт файлы из папки:
```bash
httpd -p 8080 -h ~/m10/site           # слушать порт 8080 на всех адресах
httpd -p 127.0.0.1:9090 -h ~/admin    # слушать только localhost
pkill httpd                           # остановить все свои httpd
```
На настоящем сервере на его месте будут nginx или твой бэкенд, а логика та же.

## 💼 В реальной работе

- «Сайт не открывается» → `curl -I localhost:3000` на сервере. Если бэкенд отвечает,
  проблема снаружи (firewall, nginx, DNS). Если не отвечает, смотри логи бэкенда.
- «Порт занят» → `sudo ss -tlnp | grep 3000`, найти процесс и разобраться.
- Health-check: балансировщики и Kubernetes постоянно дёргают `/health` твоего API.
- Базу и Redis слушают на `127.0.0.1`, наружу открыты только 22, 80 и 443.
