# Модуль 8. Bash-скрипты

> ⏱ ~2–3 занятия по часу

Всё, что ты делаешь руками больше двух раз, стоит превратить в **скрипт**.
Деплой, бэкап, проверка сервера, очистка логов: в DevOps это всё bash-скрипты.

## Первый скрипт

```bash
#!/usr/bin/env bash
# hello.sh — комментарии начинаются с #
echo "Привет, $(whoami)! Сегодня $(date +%F)"
```

```bash
chmod +x hello.sh     # разрешить запуск
./hello.sh            # запустить (./ — «из текущей папки»)
bash hello.sh         # или так, без chmod
```

Первая строка `#!` называется **shebang**. Она говорит системе, какой программой выполнять файл.
`#!/usr/bin/env bash` найдёт bash через `PATH`; `#!/bin/bash` тоже часто встречается.

## Переменные и кавычки

```bash
name="shop"                  # БЕЗ пробелов вокруг =
echo "$name"                 # shop
echo "${name}-api"           # shop-api — фигурные скобки отделяют имя
today=$(date +%F)            # результат команды в переменную
count=$((3 + 4))             # арифметика: 7
echo '$name'                 # $name — в ОДИНАРНЫХ кавычках ничего не подставляется
```

💡 Переменные всегда бери в **двойные кавычки**: `"$file"`. Иначе имя с пробелом развалится на два аргумента.

## Аргументы скрипта

| Что   | Значение                                    |
|-------|---------------------------------------------|
| `$0`  | имя самого скрипта                          |
| `$1`, `$2` | первый, второй аргумент               |
| `$#`  | сколько аргументов передали                 |
| `"$@"`| все аргументы (каждый отдельно)             |
| `$?`  | код возврата последней команды              |

```bash
./deploy.sh prod v2.1     # $1=prod, $2=v2.1, $#=2
```

## Код возврата (exit code)

Каждая команда, завершаясь, возвращает число: **0 — успех**, всё остальное — ошибка.

```bash
ls /etc > /dev/null; echo $?     # 0
ls /nope 2> /dev/null; echo $?   # 2
exit 1                           # завершить скрипт с ошибкой
```

Именно по коду возврата CI, cron и systemd понимают, что что-то пошло не так.

## Условия

```bash
if [[ $# -eq 0 ]]; then
  echo "Использование: $0 ИМЯ" >&2    # >&2 — сообщение об ошибке в stderr
  exit 1
fi

if [[ -f "$file" ]]; then echo "файл есть"; elif [[ -d "$file" ]]; then echo "это папка"; else echo "нет такого"; fi
```

| Проверка         | Смысл                     | Проверка        | Смысл                 |
|------------------|---------------------------|-----------------|-----------------------|
| `-f путь`        | существует обычный файл   | `-eq -ne`       | числа: равно / не равно |
| `-d путь`        | существует папка          | `-lt -gt`       | меньше / больше       |
| `-e путь`        | существует что угодно     | `== !=`         | строки: равно / не равно |
| `-z "$s"`        | строка пустая             | `&& \|\|`       | И / ИЛИ               |

Команду тоже можно проверять прямо в `if`: `if grep -q ERROR app.log; then ...`

## Циклы

```bash
for env in dev stage prod; do
  echo "Деплой на $env"
done

for f in *.log; do
  echo "$f: $(wc -l < "$f") строк"
done

while read -r line; do              # файл построчно
  echo "Строка: $line"
done < servers.txt
```

## Функции

```bash
log() {
  echo "[$(date +%T)] $*"
}
log "Начинаю деплой"     # [14:02:11] Начинаю деплой
```

Внутри функции её аргументы — это тоже `$1`, `$2`... `return 1` возвращает код ошибки из функции.

## Страховка: `set -euo pipefail`

```bash
#!/usr/bin/env bash
set -euo pipefail
```

- `-e`: остановиться на первой ошибке (а не идти дальше и всё сломать);
- `-u`: ошибка при обращении к несуществующей переменной (опечатка в имени не превратится в `rm -rf /`);
- `-o pipefail`: ошибка в любой части пайпа считается ошибкой.

⚠️ С `-e` осторожно: `grep` возвращает 1, если ничего не нашёл, и скрипт остановится.
Если ноль совпадений — это нормально, пиши `grep -c ... || true`.

## 🔧 В реальной работе

```bash
#!/usr/bin/env bash
set -euo pipefail
cd /srv/myapp
git pull
npm ci
sudo systemctl restart myapp
echo "✅ Деплой готов"
```

Такой `deploy.sh` есть почти в каждом проекте. Позже его запустит cron (модуль 9) или CI.
