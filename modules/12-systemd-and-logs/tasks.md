# Модуль 12. Задания

> ⚠️ Задания выполняются **в виртуальной машине Ubuntu** (см. раздел «Подготовка» в теории).
> Кнопка «Проверить» на сайте здесь не сработает — проверка в ВМ командой `lab check 12`.

```bash
lab setup 12
```

В `~/m12` появятся:
- `app/server.py` — учебный бэкенд (HTTP на порту 8000, `/health` и `/crash`);
- `app/.env` — его настройки (`PORT`, `APP_MESSAGE`);
- `myapp.service` — заготовка unit-файла с пропусками `???`.

Сюжет: тебе нужно «поставить на прод» бэкенд так, чтобы он сам поднимался после падений и перезагрузок.

---

## Задание 1. Осмотрись

1. Посмотри, кто работает под номером 1: `ps -p 1 -o comm=`
2. `systemctl status ssh` (или `cron`): найди строки `Loaded`, `Active`, `Main PID`.
3. Посчитай, сколько сервисов сейчас запущено, и запиши **только число** в `~/m12/running.txt`.
   Подсказка: `systemctl list-units --type=service --state=running --no-legend` + знакомый счётчик строк.
4. Посмотри последние 20 строк журнала службы `ssh`.

## Задание 2. Свой сервис

1. Сначала запусти приложение руками: `python3 ~/m12/app/server.py`, во втором окне/вкладке
   (`multipass shell lab`) сделай `curl localhost:8000/health`. Останови через `Ctrl+C`.
   Видишь проблему? Закрыл терминал — сервиса нет.
2. Открой `~/m12/myapp.service` в nano и замени все `???`:
   - `User` — твой пользователь (`whoami`), **не root**;
   - `ExecStart` — полный путь к `server.py`;
   - `Restart` — перезапуск при ошибке;
   - `WantedBy` — обычная загрузка системы (см. теорию).
3. Скопируй файл в `/etc/systemd/system/` (нужен `sudo`).
4. Попроси systemd перечитать unit-файлы и запусти сервис.
5. Проверь: `systemctl status myapp` и `curl localhost:8000/health`.

Не запускается? `systemctl status myapp` и `journalctl -u myapp -n 20` всегда расскажут почему.

## Задание 3. Автозапуск

1. Включи автозапуск `myapp`.
2. Проверь, что он переживает перезагрузку: `sudo reboot`, подожди ~30 секунд, `multipass shell lab`,
   затем `curl localhost:8000/health`.

## Задание 4. Падение

1. Узнай PID приложения (`systemctl status myapp`).
2. «Урони» его: `curl localhost:8000/crash`.
3. Через пару секунд снова `systemctl status myapp`. PID поменялся? Это systemd поднял приложение.
4. Посмотри счётчик перезапусков: `systemctl show -p NRestarts myapp`.
   (Он считает только автоматические перезапуски и обнуляется после ручного `restart`.)

## Задание 5. Журнал

1. Открой `journalctl -u myapp -f` и в другой вкладке сделай несколько запросов `curl localhost:8000/health`.
   Видишь строки запросов в реальном времени? Выйди через `Ctrl+C`.
2. Найди в журнале сообщение о падении (`FATAL`).
3. Сохрани весь журнал сервиса без листалки в `~/m12/myapp.log`.

## Задание 6. Новые настройки

1. Поменяй `APP_MESSAGE` в `~/m12/app/.env` на своё слово (латиницей, без пробелов).
2. `curl localhost:8000/health` — сообщение пока старое. Почему?
3. Сделай так, чтобы приложение подхватило новые настройки, и проверь снова.

## Бонус (по желанию)

Ищи по словам «systemd timer OnCalendar» и сравни с `crontab` из модуля 9.
