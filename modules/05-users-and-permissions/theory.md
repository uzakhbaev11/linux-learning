# Модуль 5. Пользователи и права

> ⏱ ~2 занятия по часу

Linux изначально многопользовательский: на одном сервере живут ты, коллеги, nginx, база данных, твой бэкенд.
Права доступа решают, **кто что может делать** с каждым файлом. Половина проблем «у меня не работает на сервере»
на самом деле `Permission denied`.

## Кто я?

```bash
whoami              # имя текущего пользователя
id                  # uid, основная группа и все группы
groups              # только группы
```

У каждого пользователя есть номер **uid**, а у группы номер **gid**. `root` — суперпользователь с uid 0, ему можно всё.

## Где хранятся пользователи

```bash
cat /etc/passwd     # все пользователи (паролей тут нет, несмотря на имя)
cat /etc/group      # все группы и их участники
getent passwd student   # одна запись о пользователе
getent group devs       # кто состоит в группе devs
```

Строка `/etc/passwd`, поля разделены двоеточием:
```
student:x:1000:1000::/home/student:/bin/bash
 имя    │  uid  gid    домашняя папка  shell
        └─ x = пароль хранится в /etc/shadow (его может читать только root)
```

Большинство «пользователей» в `/etc/passwd` — это не люди, а **сервисы** (`nginx`, `postgres`, `sshd`).
Каждый сервис работает от своего пользователя: если его взломают, он не сможет испортить чужие файлы.

## Читаем права: `ls -l`

```
-rwxr-xr-x  1  student  devs  1024  Nov 27 10:00  deploy.sh
│└┬┘└┬┘└┬┘     владелец группа
│ │  │  └── остальные (others)
│ │  └───── группа (group)
│ └──────── владелец (user)
└────────── тип: - файл, d папка, l ссылка
```

| Буква | Для файла         | Для папки                               |
|-------|-------------------|-----------------------------------------|
| `r`   | читать            | смотреть список файлов (`ls`)           |
| `w`   | изменять          | создавать и удалять файлы внутри        |
| `x`   | запускать         | заходить внутрь (`cd`)                  |

## Права цифрами

Каждая буква — это число: `r = 4`, `w = 2`, `x = 1`. Складываешь для каждой тройки:

| Цифры | Буквы       | Когда использовать                          |
|-------|-------------|---------------------------------------------|
| `755` | `rwxr-xr-x` | скрипты и программы, папки                  |
| `644` | `rw-r--r--` | обычные файлы, конфиги                      |
| `600` | `rw-------` | секреты: `.env`, SSH-ключи                  |
| `700` | `rwx------` | личная папка, `~/.ssh`                      |
| `770` | `rwxrwx---` | общая папка команды (владелец + группа)     |

## chmod: меняем права

```bash
chmod 600 .env              # цифрами: задать права целиком
chmod +x deploy.sh          # буквами: добавить запуск всем
chmod u+x,g-w file          # владельцу +x, группе −w
chmod o-r file              # отобрать чтение у остальных
chmod -R 755 folder/        # рекурсивно, для всей папки
```

Буквы: `u` владелец, `g` группа, `o` остальные, `a` все.

## chown и chgrp: меняем владельца

```bash
sudo chown root file            # владелец root
sudo chown www-data:www-data dir # владелец и группа сразу
chgrp devs file                 # только группа
sudo chown -R deploy /srv/app   # рекурсивно
```

Отдать файл другому пользователю может только root, поэтому нужен `sudo`.

## sudo: временно стать root

```bash
sudo команда        # выполнить от root (спросит ТВОЙ пароль, здесь: student)
sudo -i             # войти в shell root (выход: exit). Используй редко!
```

Правило: работаем под обычным пользователем, а `sudo` пишем только там, где без него нельзя.

## Группы

```bash
sudo groupadd devs              # создать группу
sudo usermod -aG devs student   # добавить student в группу devs
```

⚠️ **`-aG`, а не `-G`!** Без `-a` (append) пользователя **выкинет из всех остальных групп**.
Классическая авария: человек потерял доступ к `sudo`.

Новая группа начинает действовать после **повторного входа** в систему. В текущем терминале `id`
её ещё не покажет, а `getent group devs` покажет уже сразу.

> В Ubuntu удобнее `adduser` / `addgroup` (задают вопросы), а `useradd` / `groupadd` / `usermod` работают
> везде одинаково. В Alpine (Linux этого сайта) они тоже есть.

## umask: права для новых файлов

```bash
umask           # обычно 0022
```
umask — это права, которые **отнимаются** у новых файлов. Файл создаётся с `666 − 022 = 644`,
папка с `777 − 022 = 755`.

## 💼 В реальной работе

- `.env` с паролями от базы всегда `600`, иначе любой пользователь сервера прочитает секреты.
- SSH не пустит по ключу, если у `~/.ssh` права шире `700`, а у ключа шире `600`.
- Nginx отдаёт `403 Forbidden`: у пользователя `www-data` нет `r` на файлы или `x` на папки по пути.
- Деплой: код принадлежит пользователю `deploy`, приложение запускается от него же, а не от root.
- `chmod 777` «чтобы заработало» — красный флаг на код-ревью. Найди, кому именно не хватает прав.
