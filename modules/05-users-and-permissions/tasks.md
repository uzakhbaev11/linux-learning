## Задание 1. Кто я?

1. Выполни `id`, `whoami`, `groups`. В каких группах ты состоишь?
2. Сохрани в `~/m05/me.txt` **строку о себе** из `/etc/passwd` (только одну строку, без номера).
   💡 Пригодится `grep` с `^`, чтобы строка начиналась с твоего имени.
3. Найди в `/etc/passwd` пользователя `deploy`. Какой у него домашний каталог и shell?

## Задание 2. Читаем права

Выполни `ls -la ~/m05/app` и для каждого файла скажи вслух: кто может читать, кто писать, кто запускать.
Какие права выглядят опасно?

> У папок вместо `x` группы может стоять `s` (`drwxr-sr-x`). Это бит setgid: новые файлы внутри получают
> группу папки. В этом Linux он стоит у домашних папок, пока просто не обращай на него внимания.

## Задание 3. Наводим порядок

1. `.env` с паролями сейчас читают все. Сделай так, чтобы читать и писать мог **только владелец**.
2. `deploy.sh` не запускается. Сделай права `rwxr-xr-x` и запусти его:
   ```bash
   ~/m05/app/deploy.sh > ~/m05/deploy.out
   ```
3. `config.yml` может изменить кто угодно (`rw-rw-rw-`). Сделай нормальные права для конфига: `rw-r--r--`.
4. Папка `logs` должна быть доступна только тебе: права `700`.

## Задание 4. Только для root

`payment.key` слишком важен даже для тебя.
1. Сделай его владельцем `root` (и пользователя, и группу).
2. Права `600`.
3. Попробуй прочитать: `cat ~/m05/payment.key`. Получилось? А `sudo cat ~/m05/payment.key`?

💡 Сначала `chmod`, потом `chown`: после передачи root ты уже не сможешь менять права без `sudo`.

## Задание 5. Общая папка команды

Нужна папка, куда пишут все разработчики, но не посторонние.
1. Создай группу `devs`.
2. Добавь себя (`student`) в группу `devs`. Осторожно с флагами, перечитай теорию!
3. Сделай группой папки `~/m05/shared` группу `devs`.
4. Права на `shared`: владельцу и группе всё, остальным ничего.
5. Проверь: `getent group devs` и `ls -ld ~/m05/shared`.

> Почему `id` ещё не показывает `devs`? Группы применяются при входе в систему. Так и на реальном сервере:
> после добавления в группу нужно перелогиниться.
