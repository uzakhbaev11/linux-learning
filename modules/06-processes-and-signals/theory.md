# Модуль 6. Процессы и сигналы

> ⏱ ~2 занятия по часу

Каждая запущенная программа — это **процесс**: твой бэкенд, база данных, nginx, даже `ls` на долю секунды.
Когда «сервер тормозит» или «порт занят», ты ищешь виноватый процесс и решаешь, что с ним делать.

## Что такое процесс

- **PID** — уникальный номер процесса. По нему процессом управляют.
- **PPID** — PID родителя. Процессы образуют дерево: всех запускает кто-то другой.
- **Владелец** — пользователь, от имени которого работает процесс (и с его правами).
- У первого процесса системы PID = 1 (`init` или `systemd`), он предок всех остальных.

## Смотрим процессы

```bash
ps                      # процессы текущего терминала
ps aux                  # ВСЕ процессы системы (самая частая команда)
ps -ef                  # то же в другом формате (видно PPID)
ps aux | grep nginx     # найти нужный
pgrep -a nginx          # то же короче: PID и команда
pgrep -f "app.py"       # искать по всей командной строке, а не только по имени
pstree -p               # дерево процессов с PID
```

Колонки `ps aux`:
```
USER   PID  %CPU %MEM    VSZ   RSS TTY  STAT START  TIME COMMAND
student 812 87.0  0.3   4632  2900 ?    R    10:01  1:20 bash worker.sh
```
`%CPU` / `%MEM` — сколько ест, `STAT` — состояние (`R` работает, `S` спит, `T` остановлен, `Z` зомби).

## top и htop: диспетчер задач

```bash
top         # встроен почти везде. P — сортировать по CPU, M — по памяти, q — выход
htop        # удобнее и цветной: F6 сортировка, F9 убить, F10 выход
```

Первое, что делают при жалобе «сервер тормозит», — открывают `htop` и смотрят, кто наверху.

## Сигналы: как «разговаривать» с процессом

`kill` не обязательно убивает. Он **посылает сигнал**, а процесс решает, как реагировать.

| Сигнал    | №  | Что значит                                     | Можно перехватить? |
|-----------|----|------------------------------------------------|--------------------|
| `SIGTERM` | 15 | «Пожалуйста, завершись» (по умолчанию у `kill`) | да                 |
| `SIGINT`  | 2  | прерывание, то же, что `Ctrl+C`               | да                 |
| `SIGHUP`  | 1  | «терминал закрыт» / «перечитай конфиг»        | да                 |
| `SIGKILL` | 9  | убить немедленно, ядро просто стирает процесс | **нет**            |
| `SIGTSTP` | 20 | пауза, то же, что `Ctrl+Z`                    | да                 |

```bash
kill 812            # SIGTERM: вежливо попросить завершиться
kill -15 812        # то же самое явно
kill -9 812         # SIGKILL: убить без разговоров
pkill -f worker.sh  # послать SIGTERM всем процессам, где в команде есть worker.sh
killall htop        # всем процессам с таким именем
```

**Правило:** сначала `kill` (SIGTERM). Хорошая программа на SIGTERM сохранит данные, закроет соединения
с базой и выйдет. `kill -9` — крайняя мера: процесс умрёт мгновенно, не успев ничего сохранить.

## Фоновые задачи (jobs)

```bash
sleep 300 &         # запустить в фоне, терминал свободен
jobs                # список фоновых задач ЭТОГО терминала
fg                  # вернуть задачу на передний план (fg %2 — вторую)
Ctrl+Z              # поставить текущую программу на паузу
bg                  # продолжить задачу на паузе, но в фоне
kill %1             # послать сигнал задаче номер 1
```

Фоновая задача умрёт, если закрыть терминал: ей придёт SIGHUP. Чтобы этого не было:
```bash
nohup ./long-task.sh &      # игнорировать SIGHUP, вывод пойдёт в файл nohup.out
```

## Кто занял порт?

```bash
ss -tlnp            # TCP-порты, которые слушают программы
sudo ss -tlnp       # с sudo видно процессы ВСЕХ пользователей
```
Флаги: `t` TCP, `l` слушающие (listen), `n` цифры вместо имён, `p` показать процесс.
```
LISTEN 0 9  *:5000  *:*  users:(("httpd",pid=901,fd=3))
```
Порт 5000 слушает программа `httpd` с PID 901.

> В Ubuntu ещё часто используют `lsof -i :5000` и устаревший `netstat -tlnp`.

## 💼 В реальной работе

- `Error: listen EADDRINUSE: address already in use :::3000`: `ss -tlnp | grep 3000`, находишь PID старого процесса, `kill`.
- `docker stop` и `systemctl stop` посылают SIGTERM, ждут ~10 секунд, а потом SIGKILL. Поэтому бэкенд
  должен обрабатывать SIGTERM (graceful shutdown): дописать запросы, закрыть базу.
- `kill -HUP` у nginx и многих демонов означает «перечитай конфиг без остановки».
- Долгую миграцию по SSH запускают через `nohup` (или `tmux`), чтобы она не умерла при обрыве связи.
