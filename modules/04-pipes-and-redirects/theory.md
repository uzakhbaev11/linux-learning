# Модуль 4. Пайпы и перенаправления

> ⏱ ~2 занятия по часу

Главная философия Linux: **маленькие программы, каждая делает одно дело хорошо**,
а ты соединяешь их в цепочки. Одна строка из `grep | sort | uniq` заменяет скрипт на 30 строк.

## Три потока каждой программы

У любой запущенной программы есть три стандартных «трубы»:

| Номер | Имя      | Что это                         | Куда идёт по умолчанию |
|-------|----------|---------------------------------|------------------------|
| `0`   | stdin    | входные данные                  | с клавиатуры           |
| `1`   | stdout   | обычный вывод                   | на экран               |
| `2`   | stderr   | ошибки и предупреждения         | на экран               |

stdout и stderr оба печатаются на экран, поэтому кажутся одним и тем же. Но это **два разных потока**,
и их можно разделить. Так делают все серверы: обычный лог отдельно, ошибки отдельно.

## Перенаправления: вывод в файл

```bash
ls > files.txt          # stdout в файл (файл ПЕРЕЗАПИСЫВАЕТСЯ!)
ls >> files.txt         # stdout в КОНЕЦ файла (дописать)
ls /нет 2> errors.txt   # stderr (поток 2) в файл
cmd > out.txt 2> err.txt    # обычный вывод и ошибки в разные файлы
cmd > all.txt 2>&1      # оба потока в один файл
cmd 2> /dev/null        # ошибки выбросить
cmd > /dev/null 2>&1    # выбросить вообще всё (тихий режим)
wc -l < file.txt        # stdin ИЗ файла
```

- `>` **затирает** файл без вопросов. Одна опечатка `>` вместо `>>`, и лог за неделю пропал.
- `2>&1` читается как «поток 2 отправь туда же, куда сейчас идёт поток 1». Порядок важен:
  `cmd > all.txt 2>&1` работает, а `cmd 2>&1 > all.txt` отправит ошибки на экран.
- `/dev/null` — «чёрная дыра»: всё, что туда записано, исчезает.

## Пайп `|`: выход одной команды → вход другой

```bash
ls /etc | wc -l                 # сколько файлов в /etc
cat access.log | grep 404       # то же, что grep 404 access.log
ps aux | grep nginx             # найти процесс
history | tail -n 20            # последние 20 команд
```

Пайп передаёт только **stdout**. Ошибки (stderr) по-прежнему летят на экран.

## Инструменты для цепочек

```bash
sort file                 # отсортировать строки по алфавиту
sort -n file              # по числам (иначе 10 окажется раньше 9)
sort -nr file             # по числам, по убыванию (r = reverse)
sort -u file              # отсортировать и убрать повторы
uniq file                 # убрать ПОДРЯД идущие повторы
uniq -c file              # посчитать подряд идущие повторы
wc -l file                # количество строк
cut -d' ' -f1 file        # 1-я колонка, разделитель пробел
cut -d: -f1 /etc/passwd   # 1-я колонка, разделитель «:»
awk '{print $7}' file     # 7-е слово каждой строки
awk '$9 == 404' file      # строки, где 9-е слово равно 404
tr 'a-z' 'A-Z'            # заменить символы (здесь в верхний регистр)
tr -d '"'                 # удалить символ
head -n 5 / tail -n 5     # первые / последние строки
tee file                  # «тройник»: пишет и в файл, и дальше по пайпу
```

⚠️ `uniq` видит только **соседние** одинаковые строки. Поэтому почти всегда перед ним ставят `sort`.

## Главный рецепт DevOps: «топ чего угодно»

```bash
cut -d' ' -f1 access.log | sort | uniq -c | sort -nr | head
```

По шагам:
1. `cut -d' ' -f1` — из каждой строки взять только IP
2. `sort` — одинаковые IP встали рядом
3. `uniq -c` — посчитать каждую группу: `150 10.0.0.5`
4. `sort -nr` — от самых частых к редким
5. `head` — первые 10

Чтобы понять цепочку, собирай её **по одному звену** и смотри на вывод после каждого шага.

## `tee`: и сохранить, и посмотреть

```bash
grep ERROR app.log | tee errors.txt | wc -l
```
Строки с ERROR сохранятся в `errors.txt`, а на экран выведется их количество.
С `tee -a` файл дописывается, а не перезаписывается.

## 💼 В реальной работе

- «Кто долбит наш API?»: `awk '{print $1}' access.log | sort | uniq -c | sort -nr | head`
- «Сколько 500-х ошибок за сегодня?»: `grep " 500 " access.log | wc -l`
- Cron-задача, которая не засоряет почту: `backup.sh > /var/log/backup.log 2>&1`
- Сборка в CI: `npm run build 2>&1 | tee build.log` (видно в консоли и сохранено в файл)
- Тихая проверка в скрипте: `if grep -q "ERROR" app.log 2>/dev/null; then ...`
